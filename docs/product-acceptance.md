## 学习体系的基座与模式

本轮按“学习者在当前环节遇到的问题”组织功能，而不是按页面数量验收。以下覆盖常见路径和恢复场景，不将已实现代码称为已解决一切学习问题。新需求须能接入已有来源、学习单元和私人记录，不再单独建立一套无法回流的收藏或任务系统。

| 学习者的问题 | 基座与入口 | 验收标准及当前边界 |
| --- | --- | --- |
| 不知道今天学什么、时间很碎 | 时间预算、继续作答、未解疑问、到期复习与推荐理由 | 开始一小段即可；未完成项可改期，不要求连续打卡或额外工作映射 |
| 阅读被排版与操作打断 | 正文与目录、字号、专注、选文标注、随文笔记和提问 | 章节返回位置和私人选文保留；桌面与手机均需实际检查 |
| 前置概念没懂，无法继续 | 前置知识澄清入口带当前单元进入讨论 | 可保存疑问，理解后回到正文；不声称已有完整自动诊断或概念依赖图 |
| 收藏很多，仍未形成理解 | 资料收件箱 → 正文依据 / 观点 → 要点和具体练习 → 排期 | 延续原链接、作者与阅读问题；官方事实、作者判断、个人理解分别记录 |
| 写下答案后不知道是否理解 | 提示、参考思路、自检标准、带作答提问、自评日志 | 至少一道自己的回答才能自评；未启用模型时使用会员官网或保留疑问，不能生成模拟反馈 |
| 过几天忘记，把熟悉感当成理解 | 独立回忆模式、空白新作答、按需展开旧答案与参考思路 | 旧答案不能重复计为新复习；新旧作答可比较，规则间隔不是技能认证或 FSRS |
| 中途离开，找不到上次的工作 | 阅读位置、独立复习草稿、日志草稿与计划中的继续入口 | 刷新、返回和备份恢复后可接着写，不覆盖已保留的旧作答 |
| 标注 / 疑问 / 练习 / 资料彼此断开 | 同一学习单元 ID、原来源、章节链接与统一“接着补上这一步”事项 | 问题解决后退出未解列表，已整理的来源退出待整理列表，新的作答进入待自检 |
| 动手实验难启动，做完没留下证据 | Colab / notebook、题目中的具体输入与断言、实验日志 | 运行由学习者启动；结果可写回作答或日志，不把打开 Colab 算作实验成功 |
| 热点更新太快，旧知识混进结论 | 官方 / 论文 / 开源 / 作者来源、读取范围与日期、搜索正文适配 | 搜索到元数据不算读过全文；付费、登录或受限资料有明确人工入口 |
| 清缓存、换设备或后端暂停 | 本机记录、完整 JSON、Obsidian、导入冲突保留与可选同步 | 私人答案不进入 GitHub。Supabase / OpenAI 真实连接和双设备仍未启用 |

同一套基座支持四种进入方式：按每日时间继续、围绕一个专题深入、带具体问题查漏、探索前沿后选择值得学习的内容。读完一篇不必完成所有动作；可以只标注一句、解决一个问题或验证一道题。阅读、笔记、讨论、练习、实验与复习均应能回到同一来源和自己的历史理解。

数据关系为：来源 / 作者 / 实际阅读范围 → 学习单元 → 选文 / 疑问 / 笔记 / 作答 → 自检与复盘 → 复习和下一步。`learning-cycle.js` 只从真实记录派生阶段和待处理事项；`studyProgress.recall` 暂存本次独立回忆，已有 `answers` 保存上一次作答。结束后以日志快照保留前后比较；超长比较拆为相互链接的两篇记录。旧备份无 recall 字段仍可恢复；新增字段也进入同步文档、JSON 和 Obsidian。当前尚未部署的 Supabase 迁移同步增加该可选字段的有限结构校验。

设计依据本轮实际阅读的 [Anki 官方学习流程](https://docs.ankiweb.net/manual/studying)（先呈现问题、回忆后对照答案、自评与改期）及 [Readwise Reader 标注与笔记说明](https://docs.readwise.io/reader/docs/faqs/highlights-tags-notes)（将选文与个人笔记归属于阅读流程）。本站的分级、题目和排期规则为自身实现，没有声称复刻 Anki 算法或证明同等学习效果。

微信原生搜索已尝试：客户端触发“为了你的账号安全，请重新登录”，正常登录恢复停在“需在手机上完成登录”。因此“飞雪谈AI”的近期原文仍未读取，不能新增未经原文支持的摘要。已有公众号 ID 和来源入口保留；不会将未读内容写成已核实观点。
